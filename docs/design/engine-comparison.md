# เทียบเอนจิน: Phaser (TypeScript) กับ Unity

> ส่วนหนึ่งของ [GDD](../GDD.md) · ต้นแบบ Unity: [`prototypes/unity`](../../prototypes/unity/README.md) · สถานะ: **ตัดสินแล้ว: ใช้ Unity** ([ADR 0004](../adr/0004-unity-client.md)) · ตัวเลข WebGL ยังต้องวัดซ้ำ

## วิธีเทียบ
ทำงานเดียวกันบนสองเอนจิน คือด่าน 1-1 (ตั้งรับ 6 waves, ศัตรูชั้นยอด, คัมภีร์, ดอกเบี้ย, ดาว) โดยใช้ข้อมูลเกม `docs/data/*.json` ชุดเดียวกัน แล้ววัดสองเรื่อง
1. **ประสบการณ์ผู้เล่น:** ขนาดไฟล์, เวลาโหลด, fps บนเว็บและมือถือ
2. **ต้นทุนความถูกต้องของกฎเกม:** ถ้าใช้ Unity กฎเกมจะมีสองชุด (C# ใน client, TypeScript ในเซิร์ฟเวอร์ Node) ต้องให้ผลตรงกันทุก tick เพื่อให้รีเพลย์ ระบบกันโกง และ PvP ใช้ได้ ต้นแบบนี้จึงพอร์ตกฎเป็น C# แล้วตรวจด้วย golden replay ที่สร้างจาก TypeScript (`npm run sim:golden`)

## เทียบเชิงคุณภาพ

| ด้าน | Phaser + TypeScript | Unity 6 |
|---|---|---|
| เล่นบนเว็บทันที | เด่นที่สุด ไฟล์เล็ก โหลดเร็ว | ทำได้ แต่ไฟล์ใหญ่และเริ่มช้ากว่า โดยเฉพาะบนมือถือ |
| แอปมือถือ (store) | ผ่าน Capacitor (webview) พอสำหรับเกม 2D | **เด่นที่สุด** native, SDK โฆษณา/IAP/analytics ครบ |
| ใช้กฎเกมร่วมกับเซิร์ฟเวอร์ | **ชุดเดียว** (Node รัน sim ตัวเดียวกัน) | สองชุด (C# + TS) ต้องมี parity test ตลอด หรือย้ายเซิร์ฟเวอร์เป็น C# ทั้งหมด |
| Editor / เครื่องมือทีมศิลป์ | ไม่มี editor (ใช้ Tiled, Aseprite) | **ดีมาก** scene editor, animator, profiler |
| ภาษาไทย | ใช้ฟอนต์ของระบบ/เว็บได้ทันที | ต้องฝังฟอนต์ไทยใน build (เพิ่มขนาด) |
| หาคนในไทย | นักพัฒนาเว็บ/TypeScript มีมาก | นักพัฒนา Unity มีมาก |
| ค่าลิขสิทธิ์ | ฟรี (MIT) | ฟรีจนถึงเกณฑ์รายได้ของ Unity Personal แล้วต้องใช้แผนเสียเงิน |
| งานที่ทำไปแล้ว | ใช้ต่อได้ทั้งหมด | ต้องทำ client ใหม่ (ต้นแบบนี้คือจุดเริ่ม) |

## ผลต่อสถาปัตยกรรมถ้าเลือก Unity
- **ทางที่ 1, เซิร์ฟเวอร์ยังเป็น Node ([ADR 0003](../adr/0003-node-postgres-backend.md)):** กฎเกมสองชุด ทุกการเปลี่ยนกฎต้องแก้ทั้ง TS และ C# และรัน parity test ใน CI (ต้องมีเครื่อง CI ที่มี Unity license)
- **ทางที่ 2, เซิร์ฟเวอร์เป็น C# (.NET):** กฎเกมกลับมาเหลือชุดเดียว แต่ต้องเขียน api/game/worker ใหม่ทั้งหมด และย้าย sim/test เดิมเป็น C#
- จุดขาย "เปิดลิงก์แล้วเล่นทันที" อ่อนลง ควรปรับกลยุทธ์ไปเน้น store เป็นหลัก

## เกณฑ์ตัดสินใจ (เสนอ)
- **อยู่กับ Phaser ถ้า:** ขนาด/เวลาโหลด Unity WebGL บนมือถือแย่กว่ามาก (เช่น เกิน 3 เท่า) และทีมยังไม่ต้องการ editor มากนัก
- **ย้ายไป Unity ถ้า:** ตัดสินใจเน้น store มือถือเป็นหลัก ทีมศิลป์/ดีไซเนอร์ต้องการ editor และยอมรับต้นทุนกฎเกมสองชุดหรือเขียนเซิร์ฟเวอร์ใหม่เป็น C#
- ตัดสินใจ**ก่อนเริ่ม M1** เพราะหลังจากนั้นต้นทุนการเปลี่ยนจะสูงขึ้นมาก
