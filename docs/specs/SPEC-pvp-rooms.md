# SPEC: ศึกกับเพื่อน (ห้องเพื่อนด้วยรหัสห้อง)

> สถานะ: สร้างแล้ว รันในเครื่องเท่านั้น ยังไม่ deploy (เจ้าของตัดสิน 2026-11-08: PvP เริ่มจากห้องเพื่อน ส่วนโฮสต์และค่าใช้จ่ายจะเสนอแยก)
> โค้ด: `packages/protocol` (ข้อความและการตรวจ), `packages/game` (เซิร์ฟเวอร์), `packages/client/src/pvp.ts` และ `net.ts` (หน้าจอ)
> อ้างอิง: [SPEC-castle-battle.md](SPEC-castle-battle.md) §8 และ §14, [matchmaking.md](../design/matchmaking.md) §8, [architecture.md](../design/architecture.md), ADR 0003 และ 0007

## 1. เป้าหมาย
- ผู้เล่นสองคนเล่นศึกชิงเมือง 1v1 กันได้จริงผ่านเซิร์ฟเวอร์ โดยเซิร์ฟเวอร์เป็นผู้ตัดสินผล
- วางฐานที่ ranked และ matchmaking ใน M1–M2 ใช้ต่อได้: กฎชุดเดียว (`packages/sim`), lockstep, รีเพลย์, ตรวจ desync

## 2. กติกาของศึก
- ใช้กติกาศึกฝีมือ: `normalized: true` การ์ดทุกใบค่าพื้นฐาน มือสุ่มจากการ์ดทุกใบ (`rankedPool`)
- แต่ละคนเลือกแค่แม่ทัพกับรองแม่ทัพ (การ์ดสองใบที่ต่างกัน ไม่ใช่ธงยึดป้อม) ผ่านฟังก์ชันเดียว `pvpSetup()` ใน `packages/protocol` เพราะกติกาการจัดทัพกำลังออกแบบใหม่ เปลี่ยนที่จุดเดียวได้
- ไม่มีการสับมือในห้องเพื่อน (v1)
- ไม่มีรางวัลและไม่เปลี่ยนอันดับ
- เจ้าของห้องเป็นฝั่ง 0 (ซ้าย) ผู้มาเยือนเป็นฝั่ง 1 (ขวา) ผู้มาเยือนเห็นปราสาทตัวเองอยู่ขวา

## 3. ขั้นตอน
1. ล็อบบี้ → ปุ่ม **ศึกกับเพื่อน** (ถ้าต่อเซิร์ฟเวอร์ไม่ได้ ปุ่มกดไม่ได้และบอกเหตุผลเป็นภาษาไทย)
2. หน้าห้อง: ใส่ชื่อในศึก แล้ว **สร้างห้อง** หรือใส่รหัสแล้ว **เข้าห้อง**
3. ในห้อง: รหัสห้องตัวใหญ่ + ปุ่มคัดลอก, ช่องของสองฝ่าย (ชื่อ ทัพ พร้อมหรือยัง), เลือกแม่ทัพและรอง, ปุ่ม **พร้อม** และ **ออกจากห้อง**
4. ทั้งสองฝ่ายพร้อม → หน้าประชัน 2 วินาที → ศึก → หน้าจบ (ปุ่มหลัก: ศึกกับเพื่อนอีกครั้ง)
- **Esc:** ในห้อง = ออกจากห้อง, หน้าห้องยังไม่เข้าห้อง = กลับล็อบบี้, ในศึก = เปิดเมนู (ศึกไม่หยุด) มี "ยอมแพ้และออก"

## 4. รหัสห้องและตัวตน
- รหัส 6 ตัวจากชุด `23456789ABCDEFGHJKMNPQRSTWXYZ` (ไม่มี 0/O, 1/I/L, U/V) สุ่มด้วย `crypto.randomInt` พิมพ์เล็กหรือมีขีดได้
- ห้องที่ยังไม่เริ่มปิดเองใน 10 นาที เจ้าของห้องออก = ปิดห้อง ผู้มาเยือนออก = ช่องว่าง
- ตัวตนแบบแขก: เซิร์ฟเวอร์ออก token สุ่ม 32 ไบต์ (base64url) เก็บแค่ SHA-256 ของ token ไม่มีข้อมูลส่วนตัว ชื่อในศึกใช้ได้แค่ตัวอักษร (รวมไทย) ตัวเลข ช่องว่าง `_` `-` ไม่เกิน 16 ตัว
- ตอนนี้เก็บในหน่วยความจำ (process เดียว) **M1:** แขกย้ายไป PostgreSQL, registry ห้องไป Redis (ไม่ใช้ SQLite)

## 5. Netcode: lockstep ที่เซิร์ฟเวอร์คุม
- เซิร์ฟเวอร์รัน `createBattle(seed, pvpSetup(ทัพ0), pvpSetup(ทัพ1), { normalized: true })` ที่ 20 Hz เป็นผู้ตัดสิน
- ทุก tick ส่ง `frame { tick, cmds }` ให้ทั้งสองฝ่าย client เดิน sim ของตัวเองเฉพาะ tick ที่ได้ frame แล้ว (`Lockstep` ใน `packages/protocol`)
- client ส่งคำสั่ง `{ tick: tick ล่าสุดที่เดินแล้ว + 3, c }` (input delay 3 tick = 150 ms)
  - ถึงก่อนเวลา: รันที่ tick นั้น
  - ช้าไม่เกิน 10 tick: รันที่ tick ถัดไป
  - ช้ากว่านั้น `late`, ล่วงหน้าเกิน 40 tick `too_early`
- **ตรวจคำสั่ง:** ฝั่งต้องเป็นของผู้ส่ง (`wrong_side`), ใบต้องอยู่ในมือ (`not_in_hand`), ไม่เกิน 2 คำสั่งต่อ tick และ 6 ต่อวินาที (`too_many`); ปราณ เขตอัญเชิญ จำนวนครั้ง และปืนบรรจุ ตรวจด้วย sim เอง: ลองคำสั่งบนสำเนา state ถ้ามี event `error` ก็ไม่ใส่ใน frame (`sim`) frame จึงมีแต่คำสั่งที่มีผลจริง
- **ตรวจ desync:** client ส่ง `battleHash` ทุก 100 tick (5 วินาที) และตอนจบ ถ้าไม่ตรงกับของเซิร์ฟเวอร์: บอก client นั้น (`desync`) ผลของเซิร์ฟเวอร์ยังเป็นผลจริง และแมตช์ถูกติดธง `flagged` (matchmaking.md §8)
- **หลุด:** รอต่อกลับด้วย token 20 วินาที ต่อกลับได้จะได้ `start` พร้อม frame ที่ผ่านมาทั้งหมด แล้ว client เดินตามทัน เกินเวลา = ยอมแพ้ (`forfeit`)
- **จบ:** ผลของเซิร์ฟเวอร์เป็นผลจริง บันทึกเป็น `MatchRecord` (= `BattleRecord` + ชื่อ + ผล) ที่ `replayBattle()` รันซ้ำได้ hash เดียวกัน (ยกเว้นแมตช์ที่ยอมแพ้ ซึ่งหยุดก่อน sim จบ) `REPLAY_DIR` เขียนเป็นไฟล์ JSON

## 6. ข้อความ (protocol v1)
- client → server: `hello`, `create`, `join`, `team`, `ready`, `leave`, `cmd`, `hash`, `ping`
- server → client: `welcome`, `room`, `start`, `frame`, `reject`, `peer`, `desync`, `end`, `error`, `pong`
- ทุกข้อความตรวจด้วย schema ทั้งสองทาง: ชนิดไม่รู้จัก ฟิลด์เกินหรือขาด ชนิดข้อมูลผิด ขนาดเกิน (client 1 KB, server 256 KB) ถูกปฏิเสธทั้งข้อความ เซิร์ฟเวอร์ปิด socket ที่ส่งข้อความผิดรูป

## 7. ความปลอดภัย
- รับ WebSocket เฉพาะ origin ที่อนุญาต (ค่าเริ่ม: หน้าจาก localhost พอร์ตใดก็ได้, ตั้ง `ORIGINS` ได้) ไม่มี Origin = client ที่ไม่ใช่เบราว์เซอร์
- จำกัดต่อ IP: socket 8, สร้างห้อง 5/นาที, เข้าห้อง 10/นาที (กันเดารหัส), แขกใหม่ 10/นาที, ข้อความ 30/วินาที ต่อ socket
- ห้องสูงสุด 1,000, แขกสูงสุด 5,000 แขกที่ไม่มี socket และห้องเกิน 10 นาทีถูกลืม
- เซิร์ฟเวอร์ฟังที่ `127.0.0.1` เป็นค่าเริ่ม docker compose เปิดพอร์ตให้เครื่องนี้เท่านั้น
- ก่อน deploy จริง: ต้องใช้ `wss://` (token ส่งใน hello), ตั้ง `trustProxy` ให้ IP จริงถึงตัวจำกัด, ใช้ ticket แบบใช้ครั้งเดียวตาม ADR 0003

## 8. เวลาที่วัดได้ (loopback, `packages/game/test/timing.test.ts`)
- tick ของเซิร์ฟเวอร์ช้ากว่ากำหนด: p50 0 ms, p99 10 ms
- ระยะห่าง frame ที่ client: p50 49.9 ms
- RTT p50 0.5 ms
- คำสั่งทุกใบถึงก่อน tick ที่ประทับไว้ (เหลือ 3 tick เต็ม) ไม่มีใบไหนถูกเลื่อน
- **ยังไม่ได้วัด:** เครือข่ายจริง (ping 30–120 ms) ซึ่งจะบอกว่า input delay 3 tick พอหรือต้องปรับตาม ping

## 9. รัน
- เซิร์ฟเวอร์: `npm run dev:server` (ws://localhost:8787/v1/ws) หรือ `docker compose -f infra/docker-compose.yml up --build`
- client: `npm run dev` แล้วเปิดสองแท็บ (token เก็บใน sessionStorage แต่ละแท็บจึงเป็นแขกคนละคน ถ้าโหลดแท็บใหม่กลางศึก กดศึกกับเพื่อนภายใน 20 วินาทีก็ต่อกลับเข้าศึกเดิมได้)
- เทสต์: `npm test` (protocol, ห้อง, ทั้งแมตช์ผ่านห้อง, เวลา), ภาพ: `npm run shots:pvp`

## 10. ยังไม่ทำ
- ยอมแพ้ได้หลัง 60 วินาที (ui-flow.md §2.3): ตอนนี้ออกได้ทันทีและนับเป็นแพ้
- สับมือก่อนศึก, ดูรีเพลย์ห้องเพื่อนในเกม, ผู้ชม
- ปรับ input delay ตาม ping, version gate ของข้อมูลเกม (ตอนนี้ข้อมูลไม่ตรงจะเห็นเป็น desync)
