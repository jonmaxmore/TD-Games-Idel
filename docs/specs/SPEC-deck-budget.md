# SPEC: มือเลือกเองภายใต้แต้มทัพ (แบบ A)

> สถานะ: เจ้าของอนุมัติแบบ A (2026-11-08) ดู [deck-budget-research.md](../design/deck-budget-research.md) หัวข้อ "การตัดสินของเจ้าของ"
> แทนที่: การสุ่ม 4 ใบ กองสุ่ม รายชื่อสำรอง และการสับมือใหม่ใน [SPEC-castle-battle](SPEC-castle-battle.md) §4
> ตัวเลขอยู่ใน `docs/data/battle.json > deck` ถ้าเอกสารนี้กับ JSON ไม่ตรงกัน ให้ถือ JSON ค่าที่เขียนไว้ที่นี่คือค่าที่ `npm run sim:deck` จูนแล้ว (§7)

## 1. เป้าหมาย
- ผู้เล่นเลือกเองทั้งมือ ไม่มีการสุ่ม ไม่มีการสับมือใหม่
- กัน "ทุกคนเอาตัวแพงหรือตัวใหญ่" ด้วยแต้มทัพ ซึ่งแยกจากราคาปราณในแมตช์ (แบบ provision ของ Gwent)
- กติกาเดียวทุกโหมด: ศึกปราบ ศึกทั่วไป ศึกฝีมือ และห้องกับเพื่อน ต่างกันแค่ "ใบที่เลือกได้" และ "เลเวล"
- กติกาอยู่ใน `packages/sim` ที่เดียว ลูกค้าและเซิร์ฟเวอร์เรียกฟังก์ชันตรวจเดียวกัน (`validateDeck`)

## 2. มือ 7 ใบ
1. ตัวยึดป้อมพื้นฐานของสำนักแม่ทัพ (`hand.basic`) ใส่ให้เอง ไม่นับแต้ม
2. แม่ทัพ (`leader`)
3. รองแม่ทัพ (`sub`)
4. อีก `deck.pick` (4) ใบที่ผู้เล่นเลือกเอง (`picks`)

- มือเรียงตามลำดับนี้เสมอ ผลจึงเหมือนกันทุกเครื่อง (deterministic)
- ขนาดมือคงที่ 7 ใบ (`hand.size` = 3 + `deck.pick`)
- ทุกใบในมือลงซ้ำได้ตลอดแมตช์ภายใต้จำนวนครั้งต่อแมตช์ (`battle.json > sizes`, `perMatch`) เหมือนเดิม

## 3. แต้มทัพ
- **แต้มของการ์ด** = `deck.cardPoints[id]` ถ้ามี ไม่อย่างนั้น = ราคาปราณ + `deck.sizePoints[ขนาด]`
- **6 ใบที่ไม่ใช่ตัวยึดป้อม** (แม่ทัพ รอง และ 4 ใบที่เลือก) ต้องมีแต้มรวมไม่เกินงบ
  - งบ = `deck.budget` ทุกโหมด ยกเว้นด่านศึกปราบที่ตั้ง `deckBudget` ของตัวเอง (`campaign.json > stages[].deckBudget` ไม่บังคับ)
- **ตัวใหญ่** ใน 6 ใบรวมกันไม่เกิน `hand.maxLarge` (2)
- **ไม่จำกัดจำนวนต่อสำนัก** (เจ้าของตัดสินข้อ 4) จะเพิ่มเมื่อ `sim:deck` เจอทัพสำนักเดียวที่ชนะเกินเท่านั้น
- **แม่ทัพที่ไม่มีความสามารถ** ไม่ได้งบเพิ่ม ผลวัดอยู่ใน §7 (เจ้าของตัดสินข้อ 3 ให้ sim ตัดสิน)
- แต้มทัพใช้ตรวจตอนเริ่มแมตช์อย่างเดียว ไม่เข้าไปในกติกาการรบ
- ปรับแต้มรายใบ (`cardPoints`) และงบทุกซีซั่น กลางซีซั่นเฉพาะกรณีฉุกเฉิน (เจ้าของตัดสินข้อ 6) รีเพลย์อ้างรุ่นข้อมูลอยู่แล้ว

## 4. ใบที่เลือกได้ และใบยืม
- **ศึกปราบและศึกทั่วไป:** แม่ทัพ รอง และ 4 ใบมาจากการ์ดที่บัญชีมี (`collection.json`) เลเวลการ์ดมีผล
- **ศึกฝีมือและห้องกับเพื่อน:** เลือกได้จากการ์ดทุกใบที่ทุกคนได้ฟรีแล้ว (`collection.json > rankedPool`) งบเท่ากัน ค่าสถานะเท่ากัน (`normalized`) ของที่ซื้อได้จึงไม่เปลี่ยนพลังใน PvP (economy.md)
- **ใบยืม** (`deck.loaners`): บัญชีที่มีการ์ดที่ไม่ใช่ตัวยึดป้อมน้อยกว่า 6 ใบ ยืมใบจากรายการนี้มาเติม 4 ใบที่เลือกได้ ขนาดมือจึงเท่ากันเสมอ
  - จำนวนใบยืมในมือไม่เกิน 6 ลบจำนวนการ์ดที่ไม่ใช่ตัวยึดป้อมที่บัญชีมี
  - ใบยืมอยู่ได้แค่ในช่องที่เลือก ไม่เป็นแม่ทัพหรือรอง
  - ใบยืมนับแต้มเหมือนใบอื่น ไม่ได้แต้มฝึกหลังแมตช์ และใช้เลเวล 1 **[ความเห็น]**
  - รายการตอนนี้คือศิษย์กระบี่ราคา 2 ของทั้ง 5 สำนัก ใบถูกที่ทุกสำนักมี ไล่ตัวยึดป้อมได้ **[ความเห็น]**
  - บัญชีใหม่มีศิษย์ 3 ใบ + นักธนูพเนจร จึงยืม 2 ใบในด่านแรก
- **บอทและศัตรูของด่าน:**
  - AI ของศึกทั่วไปใช้ทัพของสำนักถัดไป (`battle.json > sectTeams`) กับ 4 ใบที่ `autoPicks` เลือกจากศิษย์ของสำนักนั้น
  - ศัตรูของด่านศึกปราบเป็นมือที่ด่านเขียนไว้ (`campaign.json > stages[].enemy.cards`) ไม่ผ่าน `validateDeck` เพราะเป็นด่านที่ออกแบบ ไม่ใช่ทัพของผู้เล่น

## 5. การตรวจตอนเริ่มแมตช์ (`validateDeck`)
- อยู่ใน `packages/sim/src/deck.ts` คืน `null` เมื่อถูกกติกา หรือรหัสข้อผิดพลาดตัวแรกที่เจอ
- ตรวจตามลำดับ:

| รหัส | เงื่อนไข |
|---|---|
| `unknownCard` | มีใบที่ไม่อยู่ใน `sects.json > roster.units` |
| `basic` | แม่ทัพ รอง หรือใบที่เลือกเป็นตัวยึดป้อมพื้นฐาน |
| `pickCount` | ใบที่เลือกไม่เท่ากับ `deck.pick` |
| `duplicate` | ใบซ้ำกันในแม่ทัพ รอง และใบที่เลือก |
| `notOwned` | แม่ทัพหรือรองไม่อยู่ในใบที่เลือกได้ หรือใบที่เลือกไม่อยู่ในใบที่เลือกได้และไม่ใช่ใบยืม |
| `tooManyLoaners` | ใบยืมเกินจำนวนที่บัญชีขาด (§4) |
| `tooManyLarge` | ตัวใหญ่เกิน `hand.maxLarge` |
| `overBudget` | แต้มรวมเกินงบ |

- **ลูกค้า** ตรวจก่อนกดเข้าศึก และแสดงเหตุผลของรหัส
- **เซิร์ฟเวอร์** ตรวจทัพที่ส่งมาด้วยฟังก์ชันเดียวกัน ทัพไม่ถูกกติกาตอบ `bad_team` และไม่เริ่มแมตช์ (SPEC-pvp-rooms)
- **`autoPicks`** สร้างมือที่ถูกกติกาจากแม่ทัพ รอง ใบที่เลือกได้ และงบ ใช้กับปุ่ม "จัดให้" และ AI ของศึกทั่วไป
  - เลือกใบที่แต้มสูงที่สุดก่อน (เท่ากันใช้ลำดับข้อมูล) โดยเหลืองบพอสำหรับช่องที่เหลือเสมอ แล้วเติมด้วยใบยืมถ้าการ์ดไม่พอ
  - `fillPicks` ทำแบบเดียวกันตามลำดับที่ส่งให้ (บอทของการวัดส่งลำดับสุ่มตาม seed)

## 6. ข้อมูล

```json
// battle.json
"hand": { "size": 7, "maxLarge": 2, "basic": { ... } },
"deck": {
  "pick": 4,
  "budget": 26,
  "sizePoints": { "small": 1, "medium": 0, "large": 2 },
  "cardPoints": {},
  "loaners": ["crimson_phoenix_blade", "jade_bamboo_blade", "cloud_sword_blade", "frost_tide_blade", "vajra_stone_blade"]
}
// campaign.json ต่อด่าน (ไม่บังคับ)
"deckBudget": 22
```

- ลบออก: `hand.redraws`, `collection.json > bench`, `collection.json > draw` และคำสั่ง `redraw` ในรีเพลย์
- `BattleSetup` (sim) = `{ leader, sub, picks, progress? }` มือมาจาก `handOf(setup)` ตาม §2
- ข้อความ `team` ของห้อง (`packages/protocol`) = `{ leader, sub, picks }`

## 7. การวัด (`npm run sim:deck`)
- สคริปต์ `packages/sim/scripts/deck-measure.ts` ทำวิธี §5.0 ของงานวิจัยซ้ำ แต่ใช้แม่ทัพและรองจริง ความสามารถเปิด
  - บอท paced, rush และ defend ทั้งสองฝั่งใช้บอทเดียวกัน
  - seed คู่กระจก: ทุก seed เล่นสองเกม สลับฝั่งซ้ายขวาด้วยการ์ดชุดเดียวกัน
  - แบบมือ (shape) กำหนดขนาดและราคาของแต่ละช่อง การ์ดจริงสุ่มใหม่ทุก seed จากการ์ดที่ตรงช่อง ใบแพงสุดเป็นแม่ทัพ ใบถัดมาเป็นรอง
  - % ชนะของแต่ละแบบ = ชนะรวมจากการพบทุกแบบที่ถูกกติกา (เสมอ = ครึ่ง)
  - ตารางรายใบ: % ชนะเมื่อการ์ดอยู่ในมือ และจำนวนมือที่มีการ์ดนั้น
- **เกณฑ์:** ทุกแบบที่ใช้งบเกือบเต็ม (ไม่ต่ำกว่างบ − 2) อยู่ในช่วง 50 ± 5 ในบอททั้งสาม ส่วนที่วัดไม่ได้ติดป้าย **NOT ASSESSED**
- **ผล (2026-11-08):** ยังไม่ผ่าน ค่าที่ดีที่สุดที่หาได้คือ งบ 26, ตัวเล็ก +1, ตัวใหญ่ +2 ห่างจาก 50 มากสุด 7.6 (paced) / 16.6 (rush) / 13.9 (defend) ตัวเลขทั้งหมดและค่าที่ลองแล้วอยู่ใน [deck-budget-research.md](../design/deck-budget-research.md) §10

## 8. หน้าจัดทัพ (ลูกค้า)
- **แสดง:** ช่องแม่ทัพ รอง และ 4 ช่องที่เลือก, แต้มของแต่ละใบ, แต้มรวม / งบ, ตัวใหญ่ x / 2, ใบยืมพร้อมป้าย "ยืม", และเหตุผลเมื่อทัพไม่ถูกกติกา (รหัสใน §5) ปุ่มเข้าศึกปิดเมื่อทัพไม่ถูกกติกา
- **ปุ่ม "จัดให้":** เรียก `autoPicks`
- **ศึกปราบ:** แสดงงบของด่านเมื่อด่านตั้ง `deckBudget`
- **ศึกฝีมือ:** แสดงทุกใบใน `rankedPool` ไม่ว่าบัญชีจะมีหรือไม่
- หน้าจัดทัพจะสร้างใหม่หลังงานปรับหน้าตาลูกค้าเสร็จ (`frontend-ui-engineering`) ระหว่างนี้ลูกค้าใช้ `autoPicks` จากแม่ทัพและรองที่เลือกไว้ และใบที่อยู่ในสำรองไม่ถูกเลือก

## 9. ไม่อยู่ในขอบเขต
- ข้อมูลที่ซ่อน (ไม่ส่งมือของคู่แข่งก่อนเวลา, ความปลอดภัย M3) และการเลือกแบบปิด (M4) ต้องตัดสินก่อนเปิดศึกฝีมือออนไลน์ เป็นงานแยก
- ระบบดราฟต์ (แบบ C) สำหรับทัวร์นาเมนต์
