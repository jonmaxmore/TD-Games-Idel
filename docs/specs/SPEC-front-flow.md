# Spec: เส้นทางผู้เล่นตั้งแต่เปิดแอปถึงเล่นด่านแรก + ความปลอดภัย zero-day

> **สถานะ: ร่าง รอเจ้าของเกมอนุมัติ**
> เจ้าของเกมต้องการให้ทุกหน้าจอถูกต้องตั้งแต่เวอร์ชันแรก: ล็อกอิน → เลือกสำนัก → lobby → loading → เล่นเกม และให้วางเรื่อง zero-day ไว้ตั้งแต่ต้น
> เกี่ยวข้อง: [sect-allegiance](../design/sect-allegiance.md) · [release-systems](../design/release-systems.md) §1, §2, §5 · [economy](../design/economy.md) · [ui-design](../art/ui-design.md) · [world-base-design](../art/world-base-design.md)

## 1. ตัวเลขจากตลาดที่ใช้ตั้งเป้า

|---|---|---|---|
| D1 retention | ค่ากลางราว 22% · 25% บนเกิน 30% (ข้อมูลปี 2025) | [InvestGame 2026 benchmarks](https://investgame.net/news/pdf/2026-01-27-2026-mobile-pc-benchmarks_compressed/) | ดี (รายงานรวมหลายเกม) |

| ขั้นตอนเริ่มเกม | เกิน 5 หน้าจอ อัตราทำจนจบต่ำกว่า 60% | อ้างผ่านบล็อกจากงานวิเคราะห์ของ UXCam ([adriancrook](https://adriancrook.com/?p=8151)) | ต่ำ (ยังหาต้นทางไม่เจอ) |

**ผลต่อเป้าของเรา:**
- **D1 ใน `economy.md`:** ตั้งไว้ ≥ 40% สูงกว่า 25% บนของตลาด (ราว 30%) มาก
  - เสนอ: เก็บ 40% ไว้เป็นเป้าท้าทาย
  - เกณฑ์ผ่าน soft launch ใช้ D1 ≥ 30%
- **เวลาถึงเกมเพลย์:** ใช้ 60 วินาทีเป็นเพดาน แม้แหล่งข้อมูลยังอ่อน เพราะตรงกับเป้า "เข้าเกม < 15 วินาที" ใน release-systems อยู่แล้ว
- **ขั้นตอนก่อนเล่น:** จำกัดไว้ไม่เกิน 3 หน้าจอ

## 2. เส้นทางที่เสนอ (เปิดเกมครั้งแรก)

```
[ไอคอนแอป] → ① Boot ≤ 3 วิ → ② ยินยอม 1 หน้า → ③ ฉากเปิด 20 วิ (ข้ามได้)
  → ④ ด่านสอน T-0 (เล่นทันที ใช้ศิษย์คละสำนัก) → ⑤ เลือกสำนัก → ⑥ ตั้งชื่อ
  → ⑦ Loading → ด่าน 1-1 ของสำนักนั้น → ผลด่าน → ⑧ Lobby (ลานสำนัก)
```

เป้า: แตะไอคอนแอปจนถึงวางศิษย์ตัวแรกใน **ไม่เกิน 60 วินาที** ถ้ากดข้ามฉากเปิด เหลือไม่เกิน 30 วินาที

**ทำไมให้เล่นก่อนเลือกสำนัก:**
- ถ้าเลือกสำนักก่อน ผู้เล่นใหม่ต้องตัดสินใจเรื่องสำคัญก่อนรู้ว่าเกมเล่นยังไง
- การย้ายสำนักต้องจ่ายเงิน (§5) ถ้าผู้เล่นรู้สึกว่าเลือกผิดตั้งแต่แรก จะเกิดความไม่พอใจและแรงต้านว่าเกมบังคับจ่าย
- ด่านสอนใช้ศิษย์คละสำนัก ผู้เล่นได้ลองทุกแบบก่อนเลือก
- ผลที่ได้: เวลาถึงเกมเพลย์สั้นลง และการเลือกสำนักมีข้อมูลรองรับ

**เปิดเกมครั้งถัดไป:** ① Boot → ⑦ Loading สั้น → ⑧ Lobby ไม่มีหน้าล็อกอิน (ล็อกอินอัตโนมัติ)

## 3. รายละเอียดแต่ละหน้าจอ

### ① Boot (โลโก้ + ตรวจระบบ)
- แสดงโลโก้ทีมพร้อมแถบโหลดบางๆ ระหว่างนั้นทำงานพื้นหลังพร้อมกัน:
  - **ตรวจเวอร์ชัน (remote config):**
    - `minVersion`: ต่ำกว่านี้ต้องอัปเดตก่อนเล่น
    - `maintenance`: แสดงข้อความและเวลาเปิด
    - `killSwitch` รายฟีเจอร์: ปิด IAP, PvP หรือ gacha ได้ทันทีโดยไม่ต้องออกเวอร์ชันใหม่ (ใช้ตอนเจอช่องโหว่ §6)
  - **ล็อกอินอัตโนมัติ:** ใช้ token guest ที่เก็บในเครื่อง
  - **ออฟไลน์:** เข้าโหมดเนื้อเรื่องได้ ซิงก์ผลเมื่อออนไลน์ ด่านที่ให้รางวัลหายากต้องให้เซิร์ฟเวอร์ตรวจ replay ก่อน
- **ต้องตรวจก่อนลงมือ:** Unity 6 ยังบังคับ splash "Made with Unity" ในแผน Personal หรือไม่

### ② ยินยอม (หน้าเดียว แสดงครั้งแรกเท่านั้น)
- ข้อตกลงการใช้งาน + นโยบายความเป็นส่วนตัว (PDPA)
- **ยืนยันอายุ:** เกิดปีไหน ต้องรู้ไว้สำหรับเพดานการใช้จ่ายของผู้เยาว์ใน economy.md ข้อ 7
- ปุ่ม "เริ่มเล่น" ปุ่มเดียว **ไม่มีหน้าล็อกอินตรงนี้** สร้างบัญชี guest ให้ทันที

### ③ ฉากเปิด (ไม่เกิน 20 วินาที กดข้ามได้)
- ภาพนิ่ง illustration 3–4 ภาพพร้อมข้อความสั้น: นิกายจันทร์โลหิตบุกหมู่บ้าน
- ใช้ภาพการ์ดชุดเดียวกับ art-bible ชั้นที่ 2 ไม่ต้องทำวิดีโอ

### ④ ด่านสอน T-0 (ด่านใหม่)
- 5 wave สั้น ได้ศิษย์ 1 ตัวจากแต่ละบทบาท แต่ละตัวมาจากคนละสำนัก
- สอน 3 อย่าง: วาง → อัป → เรียก wave เร็ว
- จบด้วยบอสเล็ก ให้รู้สึกว่าชนะได้

### ⑤ เลือกสำนัก
- **การ์ด 5 ใบ:** ภาพ illustration, ชื่อ, กฎประจำสำนัก 1 บรรทัด, ความยาก (ดาว), ตัวอย่างการเล่น 5 วินาทีแบบวนซ้ำ
- **กดการ์ดแล้วเห็นอะไร:** บทบาท 5 ตัวของสำนักนั้น และ "ลองเล่น 1 wave" ได้
- **สำนักที่ 6–7:** แสดงเป็นการ์ดล็อก "เปิดเดือนที่ 2 / 4" เพื่อบอกว่าเกมจะมีอัปเดต
- **ยืนยัน 2 ชั้น:** "เปลี่ยนภายหลังต้องใช้ป้ายย้ายสังกัด" บอกตรงๆ ไม่ซ่อน

### ⑥ ตั้งชื่อ
- มีปุ่มสุ่มชื่อแนวจอมยุทธ
- กรองคำหยาบทั้งไทยและอังกฤษที่เซิร์ฟเวอร์

### ⑦ Loading
- **เป้าเวลา:** PC ≤ 3 วินาที · Android ระดับกลาง ≤ 8 วินาที (อิงเกณฑ์ ≤ 10 วินาทีของ CrazyGames)
- **ระหว่างรอ:** ภาพสำนักของผู้เล่น + เคล็ดลับ 1 ข้อ + แถบโหลดจริง ไม่ใช่แถบหลอก
- **โหลดล่วงหน้า:** โหลดด่านถัดไประหว่างหน้าผลด่าน คนที่กด "ด่านต่อไป" จะแทบไม่เห็นหน้าโหลด
- **ขนาดแอป Android:** ไฟล์ติดตั้งแรกให้เล็กที่สุด บทที่ 2 ขึ้นไปดาวน์โหลดพื้นหลังหลังจบด่าน 1-1
  - ใช้ Play Asset Delivery + Unity Addressables
  - เป้าตัวเลขตั้งหลังวัด build จริง

### ⑧ Lobby = ลานสำนัก
- **ปุ่มใหญ่กลางจอ:** "เข้าสู่ยุทธภพ" เล่นต่อจากด่านล่าสุด กดครั้งเดียวถึงเกม
- **แถบบน:** ชื่อ ตราสำนัก ตำลึง หยก พลังงาน (ถ้ามี)
- **ข้างจอ:** ภารกิจรายวัน, กล่องจดหมาย, อีเวนต์
- **แถบล่าง 5 ช่อง:** ศิษย์ · คัมภีร์ · ลานสำนัก · ศึก (PvP/raid) · ร้าน
- **ปลดทีละขั้นตาม release-systems §5:**
  - ครั้งแรกเห็นแค่ปุ่มเข้าสู่ยุทธภพกับภารกิจ
  - ปุ่มอื่นปลดตามด่าน และมีจุดแดงบอกเมื่อปลดใหม่
- **ชวนผูกบัญชี** (Google Play Games / Apple / อีเมล):
  - ครั้งแรกหลังจบด่าน 1-3
  - ซ้ำในหน้าตั้งค่า และก่อนการซื้อครั้งแรก
  - ไม่ทำ pop-up บังคับ

### ⑨ ด่าน → ผลด่าน → ด่านต่อไป
- มีแล้วใน Unity (Retry / Next)
- เพิ่มปุ่ม "กลับลานสำนัก"
- เพิ่มรางวัลที่ได้ในหน้าผลด่าน

## 4. สิ่งที่ทำในเวอร์ชันแรก (Unity ต้นแบบ) ให้ถูกโครงตั้งแต่ต้น

ทุกหน้าจอทำเป็นของจริงตั้งแต่ตอนนี้ ใช้ภาพชั่วคราวได้ แต่ต้องใช้ลำดับ scene และ interface ที่จะใช้ตอนขายจริง

| ชิ้น | เวอร์ชันแรก (ไม่มีเซิร์ฟเวอร์) | ตอนมีเซิร์ฟเวอร์ (M1) |
|---|---|---|
| Scene | `Boot`, `Title` (ยินยอม), `SectSelect`, `Lobby`, `Loading`, `Battle` | เหมือนเดิม |
| บัญชี | `IAuthService` → guest ในเครื่อง | → API ของเรา (`packages/api`) + Google/Apple |
| เซฟ | `IProfileStore` → ไฟล์ JSON ในเครื่อง มีเลขเวอร์ชัน | → cloud save กันเซฟชนกันด้วยเวอร์ชัน |
| Remote config | `IRemoteConfig` → ไฟล์ใน build | → endpoint ของเรา |
| Analytics | `IAnalytics` → log ลงไฟล์ เพื่อดู funnel ระหว่างทดสอบ | → ผู้ให้บริการจริง (ใช้สกิล product-tracking) |

Funnel event ที่ต้องมีตั้งแต่เวอร์ชันแรก:
- `boot_start`, `consent_ok`, `intro_skip`
- `tutorial_step_n`
- `sect_view`, `sect_pick`, `name_set`
- `stage_start`, `stage_end`, `lobby_open`
- `first_place_ms` (เวลาจากเปิดแอปถึงวางศิษย์ตัวแรก)

## 5. ป้ายย้ายสังกัด (เจ้าของเกมตัดสินใจแล้ว: ย้ายสำนักต้องใช้ไอเท็ม)

- **ไอเท็ม:** "ป้ายย้ายสังกัด" ซื้อด้วยหยกหรือเงินจริงในร้าน
- **ความก้าวหน้าไม่หาย:** แยกเก็บตามสำนัก ย้ายกลับมาเมื่อไรก็ได้ของเดิมกลับมา
- **ไม่ขัดกฎ "เงินซื้อพลัง PvP ไม่ได้"** เพราะ:
  1. ranked ใช้ค่าพลังแบบ normalized
  2. ทุกสำนักผ่านเกณฑ์ S2 (win-rate ห่างกันไม่เกิน ±3%)
  - ผลคือป้ายเปลี่ยนสไตล์การเล่น ไม่ได้เพิ่มพลัง
  - **ถ้าสำนักไหนแรงเกินใน PvP ต้องแก้ด้วยการปรับสมดุลทันที** ไม่ใช่ปล่อยให้คนจ่ายเงินย้ายไปสำนักนั้น
- **ข้อเสนอเพื่อลดแรงต้านเรื่องบังคับจ่าย** (รอเจ้าของเกมตัดสินใจ):
  - ย้ายครั้งแรกฟรี ภายใน 72 ชั่วโมงแรก หรือก่อนจบบทที่ 1 สำหรับคนที่รู้สึกว่าเลือกผิด
  - ได้ป้ายฟรี 1 อันเมื่อสำนักใหม่เปิด (เดือนที่ 2 และ 4) ให้คนเก่าได้ลองสำนักใหม่ ช่วยให้อัปเดตใหญ่มีคนเล่น
  - อีเวนต์บางรอบแจกป้ายเป็นรางวัล
- **ราคา:** ตั้งตามตารางราคาใน economy.md ภายหลัง

## 6. Zero-day และความปลอดภัยตั้งแต่วันแรก

"Zero-day" คือช่องโหว่ที่ถูกเปิดเผยหรือถูกโจมตีก่อนมีแพตช์ เกมเราต้องพร้อม 2 ฝั่ง

### 6.1 ตัวอย่างจริงที่กระทบเกม Unity
- **CVE-2025-59489** ประกาศ 2 ต.ค. 2025 ([Unity advisory](https://unity.com/en/security/sept-2025-01), [Wiz](https://www.wiz.io/vulnerability-database/cve/cve-2025-59489))
  - **ช่องโหว่:** แอปที่ build ด้วย Unity ตั้งแต่ 2017.1 ถูกหลอกให้โหลดไลบรารีจากที่ไม่ปลอดภัยได้ รัน code บนเครื่องผู้เล่นได้
  - **ความรุนแรง:** CVSS 8.4 (High)
  - **ทางแก้:** ต้อง build เกมใหม่ด้วย editor ที่แก้แล้ว เช่น 6000.0.58f2, 6000.2.6f2 หรือ 6000.3.0b4 ขึ้นไป หรือใช้เครื่องมือ Binary Patch ของ Unity
  - **ข้อควรระวัง:** Binary Patch อาจไม่เข้ากับ anti-cheat
- **ของเรา:** ใช้ 6000.6.7f1 ซึ่งออกหลังแพตช์นี้ จึงน่าจะปลอดภัยจากช่องโหว่นี้ แต่ต้องตรวจกับรายการใน advisory ก่อนออกเวอร์ชันแรก
- **บทเรียน:** เกมที่ขายแล้วต้อง build ใหม่และส่งขึ้นสโตร์ได้เร็ว

### 6.2 กฎที่ใช้ตั้งแต่เวอร์ชันแรก
1. **ล็อกเวอร์ชัน Unity** ไว้ใน `ProjectVersion.txt` (มีแล้ว) และติดตาม Unity Security Advisories
   - เจอช่องโหว่ระดับ High ขึ้นไป: build ใหม่และส่งตรวจสโตร์ภายใน 72 ชั่วโมง
2. **Forced update + kill switch** ผ่าน remote config (§3 ①)
   - ใช้ได้ทันทีโดยไม่ต้องรอสโตร์ เช่น ปิดร้านค้าระหว่างแก้ช่องโหว่ IAP
3. **เซิร์ฟเวอร์ไม่เชื่อ client:**
   - ผลด่านที่ให้รางวัลตรวจด้วยการรัน sim ซ้ำ (มีอยู่แล้วในสถาปัตยกรรม)
   - receipt IAP ตรวจที่เซิร์ฟเวอร์
   - client ถูกแฮกได้ก็โกงรางวัลไม่ได้
4. **ไม่มี secret ใน client:** ไม่มี API key ของบริการเสียเงินหรือคีย์ฐานข้อมูลใน build
   - token ผู้เล่นเก็บใน Android Keystore / iOS Keychain ไม่เก็บเป็นไฟล์ธรรมดา
5. **dependency ฝั่ง Node:**
   - lockfile + `npm audit` ใน CI
   - เปิด Dependabot alerts ใน GitHub
   - ไฟล์ workflow ยังรอเจ้าของ repo ใส่ผ่าน `docs/ci/github-actions-ci.yml` เพราะผม push ไฟล์ workflow ไม่ได้
6. **ล็อกอินผ่าน token ของผู้ให้บริการเท่านั้น** (Google/Apple) เกมไม่เคยเห็นรหัสผ่านของผู้เล่น ตามแนวทาง PlayFab
7. **คู่มือรับเหตุ (runbook) 1 หน้า:** ใครตัดสินใจ, กดปิดอะไร, แจ้งผู้เล่นทางไหน, ชดเชยอย่างไร
   - ทำก่อน soft launch
   - ใช้สกิล `security-and-hardening` และ agent `security-auditor` ตรวจก่อน M1

### 6.3 Day 0 (วันเปิดตัว)
ถ้า "zero day" หมายถึงวันเปิดตัว:
- **soft launch** ที่ไทยก่อน ทดสอบโหลดเซิร์ฟเวอร์
- เปิดโหมดปิดปรับปรุงได้จาก remote config
- เตรียมของชดเชยผ่านกล่องจดหมาย
- ดู funnel §4 ทุกชั่วโมงในวันแรก
