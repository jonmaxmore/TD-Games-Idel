# ADR 0009: ภาพจาก PixelLab: sprite 96 บนกระดาน การ์ด 128 กระดานภายใน 1920x1080

- Status: accepted
- Date: 2026-11-07
- Amends: [ADR 0008](0008-pc-only-16x9.md) (กระดานเรนเดอร์ความละเอียดต่ำทั้งใบ, ภาพมาจากท่อ Blender `npm run art:build`)
- Details: [docs/tools/blender.md](../tools/blender.md) §0 (PixelLab), [docs/art/art-bible.md](../art/art-bible.md), `art/pixellab.json`, `tools/art/pixellab.mjs`, `tools/art/stylize.mjs`

## Context
- **เป้าคือหน้าตาและความรู้สึกระดับเกมขายจริงระดับ B ถึง A** เห็นการโจมตีชัด ท่าไม้ตายมีน้ำหนัก ตัวละครน่ามอง
- **ตัวละครบนกระดานยังวาดด้วยโค้ด** เป็นสี่เหลี่ยมสีประกอบกัน อ่านออกว่าใครเป็นใคร แต่ยังไม่ใช่ภาพของเกม
- **ท่อ Blender ยังเป็น proxy** และ Blender ไม่มีใน container ของ agent จึงสั่งรันและตรวจผลเองไม่ได้
- **PixelLab (pixellab.ai) สร้าง pixel art จริงจากคำบรรยาย** ผ่าน REST API v2 ล็อกสีตาม palette ได้ สร้างตัวละคร 8 ทิศในงานเดียว ทำท่าทาง (animation) และ VFX ได้
- **ขนาดที่ใช้จริงบนจอ:** กระดาน 24x12 ช่องกินพื้นที่ราว 960x600 ของเวที 1280x720 หนึ่งช่องกว้าง 40 พิกเซลเวที หรือ 60 พิกเซลจอที่ 1080p
  - ผืนภาพ 128 ให้ตัวสูงราว 100 พิกเซล หรือ 1.7 ช่อง ทับช่องข้างเคียงและทางเดิน ส่วนการย่อ pixel art ด้วยอัตราไม่ลงตัวทำให้ภาพเบลอ
  - ผืนภาพ 96 เป็นขนาด native ของ Pro Flash ตัวสูงราว 75 พิกเซล หรือ 1.25 ช่อง ยังละเอียดใกล้ภาพ 128
- **ความรู้สึกระดับ B ถึง A ส่วนใหญ่มาจากการเคลื่อนไหว เอฟเฟกต์ การตอบสนองตอนโดนตี และการโชว์ท่า** ไม่ใช่จำนวนพิกเซลอย่างเดียว

## Decision
- **บนกระดาน 96x96 วาด 1:1:** ศิษย์ ศัตรู บอส และของประกอบฉาก
  - เท้าวางบนจุดพื้นของช่อง วาดในรอบเรียงหลังไปหน้า (depth) เดียวกับของที่วาดด้วยโค้ด
  - ศัตรูหันตามทิศที่เดิน ทิศตะวันตกใช้ทิศตะวันออกกลับด้าน
  - ขั้น สายขั้น 3 สถานะ และหลอดเลือด วาดทับเป็น overlay
- **ภาพใกล้ 128x128:** การ์ดใน HUD แท็บศิษย์ หน้ารายละเอียดสำนัก และ cut-in ตอนปล่อยท่า (หน้าสรุปผลและฉากเปิดตัวบอสตามมาภายหลัง)
  - แสดงที่ 1x คมแบบ pixel เสมอ ใช้กรอบตัดภาพ ไม่ย่อ ไม่ขยาย
  - ห้ามย่อภาพ 128 ลงกระดาน ตัวไหนยังไม่มีภาพ 96 ให้กระดานวาดด้วยโค้ดต่อไป
- **กระดานภายใน 1920x1080:** บัฟเฟอร์ของ canvas เท่ากับเวที 1280x720 คูณ 1.5 แล้วให้ CSS ย่อขยายตามหน้าต่าง จึงตรง 1:1 บนจอ 1080p
  - ทุกอย่างที่วาดด้วยโค้ดวาดใต้ `setTransform(3, …)` หนึ่งช่องยังเป็น 20 พิกเซลโค้ด หน้าตาเหมือนเดิม
  - วงกลมและดวงจันทร์วาดที่ความละเอียดกระดานแล้วขยาย ขอบจึงเป็นพิกเซลกระดานเหมือนเดิม
  - `imageSmoothingEnabled = false` เสมอ ยังเป็น Canvas 2D ไม่มี WebGL ไม่มี 3D (ADR 0008 คงเดิม)
- **สไตล์ "B":** เส้นขอบภายในเป็นสี (เฉดเข้มของสีข้างเส้น) แสงเงานุ่ม
  - เส้นนอกสุดของ silhouette ใช้โทนเข้มสุดของกลุ่มสีหลักของภาพนั้น ไม่ใช้ดำล้วน ตัวละครจึงแยกจากหญ้าและถนน
  - `tools/art/stylize.mjs` ทำสองอย่างนี้กับทุกภาพที่ดาวน์โหลด ผลแน่นอน (deterministic) และทุกพิกเซลอยู่ใน `effects.json > render.palette`
  - ในเกมมีขอบ 1 พิกเซลรอบ sprite บนกระดาน: สีสำนักสำหรับศิษย์ แดงสำหรับศัตรู ทองเมื่อเลือกหรือชี้ ทำไว้ล่วงหน้าครั้งเดียวต่อภาพต่อสี ไม่มีบนการ์ด
  - ความสม่ำเสมอของชุดภาพมาจากการส่ง sprite ที่อนุมัติแล้วของเราเป็น `style_image` (`style_options {outline, shading}`) ภาพอ้างอิงสไตล์ B ไม่เคยถูกส่งให้ PixelLab
- **ความรู้สึกตอนสู้ทำในเอนจิน จาก event ของ sim ที่มีอยู่ ไม่แตะกฎ:** ก้าวพุ่งพร้อมยืดหด กระพริบขาว กระเด็นสั่น หางกระสุนตามชุดวิชา ควันตอนตาย แสงเรือง (`lighter`) สีจาก palette hit-stop และจอสั่นตามดาเมจ (ตามค่าตั้งจอสั่น) และ cut-in ท่าไม้ตาย 0.6 วินาที
- **อะไรที่ยังไม่มีภาพใช้ภาพวาดด้วยโค้ด** `packages/client/public/sprites/manifest.json` บอกว่ามีไฟล์อะไร client โหลดครั้งเดียวตอนเริ่ม
- **ตัวสร้างภาพคือ `npm run art:pixellab`** (`tools/art/pixellab.mjs` อ่าน `art/pixellab.json`)
  - วางแผนตัวละคร 8 ทิศ ท่าโจมตีและร่ายวิชา 4 ทิศสำหรับศิษย์ ท่าเดินและท่าโดนตี 4 ทิศสำหรับศัตรู ของประกอบฉาก และ VFX ต่อชุดวิชา
  - ข้ามงานที่มีไฟล์แล้ว เก็บ job id ไว้ใน `art/pixellab-jobs.json` รันซ้ำแล้วไม่จ่ายซ้ำ
  - `--dry-run` บอกจำนวน generation ก่อนจ่ายจริง ถามราคาจาก `GET /v2/pro-flash/cost` ซึ่งฟรีและไม่ต้องใช้ token
  - ดาวน์โหลดผ่าน `api.pixellab.ai` เท่านั้น ไม่ใช้ `backblaze.pixellab.ai` (ถูกบล็อก)
- **Blender เป็นทางเลือก ไม่ใช่ทางหลักอีกต่อไป** ใช้ปั้นภาพโปรโมต ฉาก หรือภาพที่ PixelLab ทำไม่ได้

## Consequences
- **กฎ palette ยังบังคับเหมือนเดิม** `npm test` ตรวจทุกพิกเซลที่ไม่โปร่งของทุก PNG ใต้ `public/sprites` ว่าอยู่ใน `render.palette` และไม่มีพิกเซลโปร่งครึ่งๆ
- **manifest ตรงกับไฟล์เสมอ** test เทียบ `manifest.json` กับไฟล์บนดิสก์ และเทียบ `art/pixellab.json` กับ `docs/data`
- **บัฟเฟอร์ใหญ่ขึ้น 2.25 เท่า** (1500x1005 แทน 1000x670 ต่อกระดาน) ต้องวัด fps ที่ x16 บน 1-12 ทุกครั้งที่เพิ่มเอฟเฟกต์ เกณฑ์คือ 60 fps
- **ค่าใช้จ่าย:** `--dry-run` ของแผนเต็มประเมิน 527 generation (ตัวละคร 147, การ์ด 54, ของประกอบฉาก 55, ท่าทาง 252, VFX 19) ราคาตัวละคร การ์ด และของประกอบฉากมาจาก cost endpoint (provisional) ส่วนท่าทางและ VFX ใช้ราคาที่ PixelLab ประกาศ ต้องใช้แผนแบบจ่ายเงิน บัญชีทดลองเหลือ 3 generation และรันได้ทีละงาน
- **งานนำร่องตอนนี้มีแค่การ์ด 128 ของ `crimson_phoenix_striker`** ผ่าน post-process แล้ว ภาพ 64 เดิมถูกถอด กระดานยังวาดด้วยโค้ดจนกว่าจะมีภาพ 96 ภาพแรกที่ผ่านการอนุมัติ
- **ท่าทางยังไม่ถูกใช้ในเกม** ตัวสร้างภาพเก็บเฟรมไว้ที่ `board/<id>/anim/<ท่า>/<ทิศ>/<n>.png` การเล่นเฟรมในเกมเป็นงานรอบถัดไป ระหว่างนี้การก้าวพุ่งและยืดหดทำในเอนจิน
