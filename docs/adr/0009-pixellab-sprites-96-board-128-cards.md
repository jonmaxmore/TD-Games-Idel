# ADR 0009: ภาพจาก PixelLab: sprite 96 บนกระดาน การ์ด 128

- Status: accepted
- Date: 2026-11-07
- Amends: [ADR 0008](0008-pc-only-16x9.md) (กระดานเรนเดอร์ความละเอียดต่ำทั้งใบ, ภาพมาจากท่อ Blender `npm run art:build`)
- Details: [docs/tools/blender.md](../tools/blender.md) §0 (PixelLab), `art/pixellab.json`, `tools/art/pixellab.mjs`

## Context
- **ตัวละครบนกระดานยังวาดด้วยโค้ด** เป็นสี่เหลี่ยมสีประกอบกัน อ่านออกว่าใครเป็นใครจากสีชุดกับอาวุธ แต่ยังไม่ใช่ภาพของเกม
- **ท่อ Blender ยังเป็น proxy** asset ใน `art/manifest.json` ประกอบจากรูปทรงพื้นฐาน ยังไม่มีโมเดลจริงสักตัว และ Blender ไม่มีใน container ของ agent จึงสั่งรันและตรวจผลเองไม่ได้
- **PixelLab (pixellab.ai) สร้าง pixel art จริงจากคำบรรยาย** ผ่าน REST API v2 ล็อกสีตาม palette ที่ส่งไปได้ และสร้างตัวละคร 8 ทิศในงานเดียว
- **งานนำร่องผ่านแล้ว:** ศิษย์ขนหงส์เจาะ (`crimson_phoenix_striker`) ขนาด 64 (หันหน้า) และการ์ด 128 ทุกพิกเซลอยู่ใน `effects.json > render.palette` ไม่มีพิกเซลโปร่งครึ่งๆ
- **กระดานเดิมวาดที่ความละเอียดต่ำ** 1 พิกเซลของกระดาน = 2 พิกเซลจอที่ 720p ถ้าวาด sprite 64 ลงบัฟเฟอร์นั้น sprite จะใหญ่ขึ้นสองเท่าและพิกเซลหยาบไม่เท่ากับงานที่ได้มา

## Decision
เจ้าของเกมเลือกให้ภาพมาจาก PixelLab เป็น sprite pixel art จริง
- **บนกระดาน 64x64:** ศิษย์ ศัตรู บอส และของประกอบฉาก (บ้าน ต้นไม้ ศาลเจ้า หิน กอไผ่ น้ำแข็ง แผงตลาด ซากวิหาร โคมไฟ ธง ประตูสำนักแบบโทริอิ)
  - วาด 1:1 กับพิกเซลจอ เท้าวางบนจุดพื้นของช่อง
  - วาดในรอบเรียงหลังไปหน้า (depth) เดียวกับของที่วาดด้วยโค้ด
- **บนการ์ด 128x128:** การ์ดศิษย์ใน HUD, แท็บศิษย์ในลานสำนัก และหน้ารายละเอียดสำนัก
  - แสดงคมแบบ pixel (`image-rendering: pixelated`) ขนาด 1x เท่านั้น
  - การ์ดใน HUD แสดงแถบหน้าและไหล่จากภาพ 128 ที่ 1x (ตัดกรอบ ไม่ย่อ) เพราะแผงข้างกว้าง 280 px
- **กระดานยังเป็น Canvas 2D บนเวที 1280x720** ไม่มี WebGL ไม่มี 3D (ADR 0008 คงเดิม)
  - บัฟเฟอร์ของ canvas เปลี่ยนเป็นความละเอียดเต็ม (1 พิกเซลบัฟเฟอร์ = 1 พิกเซล CSS ที่ 720p)
  - ทุกอย่างที่วาดด้วยโค้ดวาดใต้ `setTransform(2, …)` จึงหน้าตาเหมือนเดิมทุกพิกเซล รวมตัวเลข วงระยะ และเคอร์เซอร์
  - sprite วาดที่สเกล 1 บน canvas เดียวกัน
- **อะไรที่ยังไม่มี sprite ใช้ภาพวาดด้วยโค้ดเหมือนเดิม** เกมจึงเล่นได้เสมอแม้มีภาพไม่ครบ
  - `packages/client/public/sprites/manifest.json` บอกว่ามีไฟล์อะไรบ้าง client โหลดครั้งเดียวตอนเริ่ม ไม่ต้องลองยิงหาไฟล์ที่ไม่มี
- **ตัวสร้างภาพคือ `npm run art:pixellab`** (`tools/art/pixellab.mjs` อ่าน `art/pixellab.json`)
  - หนึ่งรายการต่อ asset: id, ชนิด (`character` | `object` | `card`), ขนาด, คำบรรยาย, กลุ่มสี
  - id มาจาก `docs/data` (ศิษย์ใน `roster.units`, ศัตรูและบอสใน `enemies.json`, ของประกอบฉากใน `maps.json > propTypes`)
  - ข้ามไฟล์ที่มีอยู่แล้ว ทีละงาน (`--concurrency` ปรับได้) `--dry-run` บอกจำนวน generation ที่จะใช้ก่อนจ่ายจริง
- **Blender เป็นทางเลือก ไม่ใช่ทางหลักอีกต่อไป** ใช้ปั้นภาพโปรโมต ฉาก cut-in หรือภาพที่ PixelLab ทำไม่ได้

## Consequences
- **กฎ palette ยังบังคับเหมือนเดิม** `npm test` ตรวจทุกพิกเซลที่ไม่โปร่งของทุก PNG ใต้ `public/sprites` ว่าอยู่ใน `render.palette` และไม่มีพิกเซลโปร่งครึ่งๆ
- **manifest ตรงกับไฟล์เสมอ** test เทียบ `manifest.json` กับไฟล์บนดิสก์ และเทียบ `art/pixellab.json` กับ `docs/data` ว่าครบทุกศิษย์ ศัตรู บอส และของประกอบฉาก
- **sprite ตัวใหญ่กว่าตัววาดด้วยโค้ด** 64 พิกเซลสูงราว 1.6 ช่อง (ช่องกว้าง 40 พิกเซลจอ) ตัวที่ยืนช่องหลังบังช่องหน้ามากขึ้น ต้องดูใน `npm run shots` ทุกครั้งที่เพิ่มภาพ
- **ค่าใช้จ่าย:** manifest เต็มชุดประเมินไว้ 241 generation (ตัวละคร 8 ทิศ 6, ของประกอบฉาก 5, การ์ด 6 ต่อชิ้น จาก `GET /pro-flash/cost` ค่าประมาณ ยังไม่ใช่ราคาจริง) บัญชีทดลองมี generation จำกัดและรันได้ทีละงาน
- **งานนำร่องมีแค่ทิศใต้** ไฟล์ 64 ของ `crimson_phoenix_striker` มาจาก `create-image-pro-flash` ไม่ใช่ตัวละคร 8 ทิศ ตัวสร้างภาพจะข้ามเพราะมีไฟล์แล้ว ถ้าต้องการครบ 8 ทิศให้ลบโฟลเดอร์นั้นแล้วรันใหม่
- **ยังไม่มีท่าทาง** sprite เป็นภาพนิ่งหนึ่งเฟรมต่อทิศ การขยับตัว การกระพริบตอนโดนตี และสีสถานะทำในเอนจิน (เงาสีทับ silhouette) ท่าเดินและท่าโจมตีเป็นงานรอบถัดไป
- **ศัตรูหันตามทิศที่เดิน** ตะวันออก ตะวันตก ใต้ เหนือ ถ้าไม่มีทิศตะวันตกใช้ทิศตะวันออกกลับด้าน ศิษย์หันทิศใต้เสมอ
