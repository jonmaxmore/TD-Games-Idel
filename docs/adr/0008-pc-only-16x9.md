# ADR 0008: PC only, 16:9, 2.5D pixel art (no 3D)

- Status: accepted
- Date: 2026-11-06
- Amended by: [ADR 0009](0009-pixellab-sprites-96-board-128-cards.md) (board buffer 1920x1080 per stage, PixelLab sprites 96 on the board, 128 card art)
- Amends: [ADR 0007](0007-typescript-threejs-node.md) (drops the Capacitor mobile build and three.js) and the "web first, then mobile" plan in GDD §10

## Context
The owner decided to make the game for PC only, in 16:9, as 2.5D pixel art, and to remove 3D entirely.

## Decision
- **2.5D pixel art, no 3D.** The board is drawn with plain Canvas 2D:
  - It is a 3/4 top-down view, with tiles 24x15 pixels, the ground squashed vertically.
  - Disciples, enemies, rocks and the gate stand upright as pixel figures, drawn back to front.
  - It renders at low resolution in whole pixels, and CSS scales the canvas up with hard edges (a whole-number scale where it fits).
  - three.js and WebGL are removed.
  - Figures are drawn in code until the art pipeline (`npm run art:build`, Blender to pixel sprites) has frames for every unit and enemy.
- **One screen shape.** The client lays everything out on a fixed 1280x720 stage and scales it to the largest 16:9 box that fits the window. Letterbox bars fill the rest.
- **The battle screen** has a top bar across the screen, the board on the left and a 360 px side panel on the right (cards, the selected disciple, secret arts, the wave button). The board's long side (18 tiles) runs across the wide screen.
- **Mouse and keyboard.** 1-9 pick a disciple card, Space calls the next wave, U upgrades the selected disciple, P pauses, Esc clears the selection.
- **The build is the browser game.** A desktop wrapper (e.g. for Steam) comes later if needed. No Capacitor, no touch layout and no mobile store build.
- **Visual proof** (`npm run shots`) runs at 1280x720.

## Consequences
- **One layout to design, test and balance the UI for.** There are no safe-area insets and no portrait screens.
- **Design docs written for mobile need a pass before they drive any work.** Among them:
  - store IAP and the monthly card through app stores (`docs/design/economy.md`)
  - push notifications
  - "60fps on a mid-range phone"
  - the iOS launch in ADR 0004
- **Payments.** They must come from a PC channel (web payments or a desktop store) instead of the app stores. That is a product decision still open.
